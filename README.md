# CodeCartia（源图）

面向开发者的本地跨语言代码理解、架构探索与业务场景理解工具。目标是将跨文件、跨工程和跨语言的源码关系绘成可探索的地图，以业务场景和逻辑为主线，在具体步骤、动作和对象内解释参与角色、授权条件与实现依据，帮助开发者判断修改影响。

**当前处于 M1「契约与验证原型」的实施准备：M1-01 文档交付已完成，M1-02 的四份统一契约草案已交付并通过文档交叉复核。** 仓库包含设计方案 v0.6、审查与修订记录、推进方案 v0.4、验收样例 v0.3、实施追踪和契约草案，另有 HTML 设计图解、基于模拟分析结果的产品体验原型及可运行采购示例。M1-02 的跨语言真实事实核对仍待执行，下一项可开始的是 M1-03 worker 协议草案。CodeCartia 的 CLI、产品 Web、自动分析器、分析验证原型及规则迭代功能尚未实现，也没有发布包；M1 基线未冻结、G1 未通过。示例功能测试和体验原型不代表产品分析验收通过。下列内容是已确认的产品目标，实际支持范围将在实现与验收后公布。

## 产品目标

- 采用 **CLI＋本地 Web 界面**，管理一个或多个工程，提供系统总览、模块与文件、业务流程、符号与调用视图。
- 从业务总览进入场景、步骤/动作及操作对象，解释业务规则、状态操作、异常和输出；每步直接关联参与者、实际角色映射、授权条件、数据范围及入口检查点，结论可追溯证据。
- 角色或权限查询反查同一套场景步骤，支持跨场景复用和条件矩阵，各动作保留自身上下文；未关联声明保留诊断，不生成虚构业务。业务参与者、认证、前端可见性与后端授权分别表达。
- 以静态分析建立关系，每条确认关系保留源码或明确元数据依据；动态行为保留候选、条件和未解析状态。
- 关联前端请求与后端端点，并分析 WebSocket、进程、文件及常见 FFI 边界。
- AI 可选用于解释已有证据、辅助识别及归纳改进规则；核心静态功能的设计不依赖 AI。
- 首版包含跨项目改进闭环：**发现错连或漏连 → AI 提出候选规则 → 源码与语义核对 → 独立项目验证 → 回归测试 → 版本化固化与回滚**。

## 首版目标范围

| 工程类别 | 目标语言与框架 |
|---|---|
| 前端 | 原生 JavaScript、Vue、React，以及常用的 TypeScript、JSX、TSX、HTML 与配置文件 |
| 后端与全栈 | Java、C#、Node.js、Next.js、C、C++、Python；Next.js 按全栈框架分析 |

**首版所有目标语言同步达到深度分析要求。** 内部可以并行实现，但首版发布以各适配器分别通过验收为前提；仅完成语法索引不能计为深度分析完成。框架版本、编译上下文与具体验收口径详见设计方案。

[阅读完整设计方案 v0.6](docs/CodeCartia-设计方案.md)（2026-11-09），其中包含架构、语言与框架能力矩阵、关系与证据模型、业务步骤内的角色授权、跨工程关联、质量验收和 AI 跨项目改进。本版明确步骤绑定、同图角色反查及未关联诊断，并保留渲染、HTTP 分发和权限判定对照要求。

[阅读设计审查报告](docs/CodeCartia-设计审查报告.md)，查看原问题复核、v0.3/v0.4 修订、v0.5 的 R08–R10 及 v0.6 的业务主线修订记录。相关契约均需后续原型和产品验收。有限数据流规则细表纳入第一里程碑；用户已确认核心验收采用自动静态分析结果，AI 辅助与人工调整分别报告。当前完成的是设计文档与验收规格，尚未进行实现验证。
