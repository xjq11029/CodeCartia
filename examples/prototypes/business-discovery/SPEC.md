# 有限模式、原始输入与判据

本规格先于提取器验证结果确定语义预期。`expected/` 由原始源码和技术 API 契约手工标注，`evaluate.py` 不导入提取器；两者与提取器同次开发，仍属于公开开发回归，不能冒充独立人员或独立保留项目验收。

## 输入边界

提取器仅读取参数所指工程的 `project.json` 及其中登记的平面 `.py` 文件、当前实验的 `technical-profile.json` 和它引用的技术契约。每份源码只捕获一次原始 UTF-8 字节，同一份字节同时用于 AST 与证据指纹，保留 LF/CRLF 与 Unicode。配置和技术文档也从单次读取产生指纹。输入捕获是逐文件读取，不提供文件系统原子快照；结果准确标识所捕获版本，评估时磁盘内容变化会导致指纹不匹配。

不运行被分析模块，不读取预期、评估器或任何业务词典；标准库自身加载不属于被分析工程输入。提取器 CLI 和验证器统一通过 `report_io.py` 写入本目录 `reports/` 下的 JSON 文件，核对未解引用的原始路径、最终目标及逐级父目录，拒绝已存在的 symlink、junction/reparse point，不能覆盖输入、预期或分析代码。这是写前链接拒绝策略，不提供并发替换链接时的原子隔离保证。

模块级只接受登记模块间的显式导入、无装饰器/默认参数/可执行类型注解的函数，以及登记的顶层入口注册。技术框架文件只能具有被校验的表初始化、函数与异常类。外部导入、重复绑定、重新赋值、任意类或模块级副作用拒绝整次实验，防止忽略名字被替换后仍沿旧函数解释。

## 支持模式

| ID | 前提、提取行为 | 失败边界 |
|---|---|---|
| BD01 顶层入口 | 登记 API 的三个位置参数为字面量方法、地址和可定位函数；每个完整注册行列锚点形成一个场景，名称采用原始锚点模板；同行同地址及重复处理器仍保留不同注册身份 | 身份仅限捕获输入版本，不替代产品稳定身份注册；动态地址/处理器保留项目诊断，不做 HTTP 分发或不同入口的业务归并 |
| BD02 跨函数参数 | 显式本地/导入函数、必填位置参数；按调用点将实参替换到形参，保存完整调用路径与参数绑定；使用 Python symtable 预先检查整函数词法作用域 | 后置局部赋值、def、import、del、循环目标等都可使前面同名调用无法指向模块 API；此时保留未知，不先发布保护关系。global/nonlocal、关键字/展开参数、闭包、递归、动态调用和普通赋值别名不在支持范围 |
| BD03 条件与检查 | 仅接受名称、属性、常量、比较、AND/OR/NOT 表达式；技术契约区分授权和业务检查，且 API 实现和异常类通过 AST 形状校验 | 调用型谓词、未知 API、写后再检查、复杂运算保留未知；不通过角色字段名、错误文字或异常名自行分类 |
| BD04 步骤和对象 | 条件检查、直接参数对象的字段赋值构成步骤；对象由实参绑定得到，动作名称/字段/值来自源码 | `memory-write` 仅表示字段赋值语法及所列正常路径，不证明 `__setattr__`、描述符、数据库或持久化效果，不执行表达式 |
| BD05 授权绑定 | 已知授权检查的对象与当前步骤对象经调用点替换后相同，且检查是该步骤的前缀条件时，引用同一检查 ID、主体和对象 | 不同符号未证明别名时不互相覆盖；未登记守卫不进入授权列表；不输出指定用户的确定 allow/deny |
| BD06 未知保留 | 仅含 `if condition: raise` 的未登记守卫保留 `unclassified-guard` 及进入后续步骤需满足的否定条件；动态调用保留 `unknown-call` | 未知调用及不能解释的普通语句截断后续展开；未知不解释为拒绝、匿名或场景不可用 |
| BD07 共享实现 | 两个场景步骤引用相同限定函数时登记共享实现；各场景调用点、条件、对象和检查绑定独立 | 不按共享审计、角色或普通调用合并场景 |

预算为最大调用深度 8、每场景已提取步骤 100；触发预算追加明确诊断并停止后续展开。这只是当前实验的确定上限，不是产品 D04/D08 冻结决定。函数正常返回仅结束其内部展开；不把调用动作视为已成功执行。

`requires` 引用之前检查在其**原始执行位置**上的成功分支，不能在字段修改后重新解释为当前值仍满足同一谓词。`same-object-call-prefix` 表示源码调用前缀覆盖，不承诺资源始终不变、检查足够安全或整个动作已获授权。当前不分析身份认证来源、不求解具体主体属性、跨对象别名、异常捕获、异步、事务及实际结果，故场景 `authorizationDecision` 与绑定 `decision` 均为 `unknown`。

`complete=true` 只表示场景在本表有限语法/技术模式内完成展开；不表示项目全部业务或完整授权分析通过。静态条件只是条件表达式，没有被执行或当作查询已满足。

## 两个原始工程与独立预期

- `inputs/library/`：借阅领域，入口包装函数、服务实现、共享审计分处三个模块。两个入口具有不同检查和状态赋值，共用 `shared.record`，预期为两个独立场景、8 个步骤和两组有据绑定。
- `inputs/publishing/`：内容发布领域，模块别名调用技术 API，处理器与共享函数位于同一模块。发布路径带动态回调，撤回路径有语义未分类的守卫；预期为两个场景、9 个步骤和两个部分结果，共用 `application.stamp`。

原始项目配置只列工程 ID 和输入文件，不列场景名、路径、角色、对象、步骤或预期授权。领域值来自源码。与已有采购演示不同，本实验的结构直接由源码 AST 生成；它仍只验证这两个公开合成工程，不构成跨项目泛化证明。

## 独立匹配与必须拒绝的结果

匹配键为方法、地址、限定入口函数与注册锚点。场景集合必须完全一致，步骤按源码展开次序比较类型、实现、主体、对象、条件、字段/值、前缀检查与授权检查索引；调用边、实参/形参映射、完整调用路径、诊断、局部完整性与共享实现集合也须一致。只忽略输出场景的无语义排列顺序，不忽略步骤顺序、条件或额外候选。空预期、空输出和重复的同一注册身份均不能通过；同处理器被不同注册锚点引用不是重复输出。

每条入口、调用和步骤证据都核对登记文件、原始字节指纹、Python UTF-8 字节列和原始文本，还必须匹配独立预期冻结的 AST 锚点、语法种类和所属函数；不能拿另一处真实源码充当依据。技术 API 必须属于登记类别、原调用在其词法作用域中确实指向该 API，并强制提供相应实现的技术证据。登记配置、技术 profile 和技术契约的指纹分别核验。检查绑定必须引用同一场景中此前存在的授权检查，其对象、主体及覆盖条件不能伪造；场景/步骤 ID 全局唯一并与完整注册位置一致。

评估器至少拒绝：空输出、额外场景、假候选、假步骤、缺跨函数步骤、缺调用、错对象授权、把业务检查伪造为授权、遗漏条件、假 allow、错证据、合并共享场景、错输入配置指纹、错技术 profile/契约指纹、错 API 分类、拿合法但无关源码替换依据、缺技术依据、错参数映射、伪造调用路径中间节点、重复场景/步骤 ID，以及隐藏未知。`verify.py` 对实际输出分别施加这些变异，要求每个变异失败。

源码对照另外验证：替换领域路径与角色值并使用 Unicode/CRLF 后仍按新源码提取；改变 API 拒绝逻辑被拒绝；对另一对象执行共享函数不继承原对象检查；写后再检查保留未知；输入读取后立即变化不会让旧 AST 绑定新字节指纹；模块 API 名字重新绑定被拒绝；函数后置局部声明或导入别名遮蔽不能先输出确认检查；global 声明保留未知；同行同地址及重复处理器分别保持独立注册身份；CLI 不得写入输入、预期或代码。这些是支持边界对照，不新增产品验收承诺。

输出辅助脚本也必须遵守同一写入规则。验证器为父目录和最终目标各创建真实目录链接，仅指向本实验新建的临时哨兵，分别调用 CLI 和验证器写入口，要求拒绝且哨兵不变；清理时只删除链接本身。当前 Windows 使用原生 junction 实测，非 Windows 的目录 symlink 分支尚未实测；文件 symlink 与恶意并发换链另属未验证边界。
