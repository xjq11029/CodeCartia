# 业务发现有限模式实验

本目录用 Python 标准库 AST 对两个不同领域、不同代码组织的公开合成工程进行只读分析：模块化借阅服务与单文件发布服务。它验证从原始入口注册、跨函数调用、检查和字段赋值中自动形成步骤及授权绑定；不是产品分析器、完整 BS/AP 基准或独立保留项目，不证明跨语言或任意项目泛化。

提取器不执行被分析代码，也不读取 `expected/`。`technical-profile.json` 只登记合成框架的技术 API、参数位置和拒绝异常；不登记场景、步骤、业务对象、角色、地址或预期结论。API 分类的独立依据见 [技术 API 契约](TECHNICAL-API.md)，其源码形状也需经 AST 校验。未登记守卫保留未知，不按函数名或错误文案猜测权限。

| 文件或目录 | 内容 |
|---|---|
| [SPEC.md](SPEC.md) | 有限支持模式、未知边界和独立匹配口径 |
| `inputs/` | 两个原始工程及只含输入文件列表的登记 |
| `expected/` | 独立手工预期；仅评估器可读取 |
| `extract.py` | 只读 AST 提取、参数替换、步骤及检查覆盖 |
| `report_io.py` | 提取器与验证器共用的报告写入边界，拒绝父目录或最终路径的链接 |
| `evaluate.py`、`verify.py` | 独立评估、空结果/假结果/遗漏等变异检查及重命名对照 |
| `reports/` | 实际提取结果、机器验证结果与实验说明 |

执行目录为本目录：`python verify.py`。单独提取：`python extract.py --project inputs/library --output reports/library.json`。仅需要 Python 标准库；准确运行环境、通过情况和限制以 [实验报告](reports/REPORT.md) 及 `reports/verification.json` 为准。

场景名称只用“方法 地址 → 处理器”模板；相同实现不会合并入口场景。检查绑定只说明指定 API 在所列源码路径上约束相应对象，不计算具体用户的 allow/deny，不证明运行效果或持久化成功。全部输出仍为实验局部结构，尚未适配产品公共 schema。

当前 Windows 已实际验证报告父目录和最终路径的目录 junction 均被 CLI、验证器拒绝，临时哨兵未被覆盖。文件 symlink、其他平台和并发替换链接竞态未实测；不以目录链接检查宣称完整文件系统隔离。
