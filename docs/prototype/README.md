# 产品体验原型

[打开成品 HTML](index.html)，可用 Chrome 等浏览器直接离线阅读，无需启动服务或安装依赖。

本原型展示 CodeCartia 完成后分析一个采购前后端工程的阅读体验：以同一申请的状态生命周期为入口，展开业务条件、成功/失败分支、事务边界与返回结果，再定位每个业务环节对应的代码、调用关系和源码。业务流程、步骤授权、代码地图、条件矩阵和未关联/候选诊断共用同一份模拟结果。

代码地图中的“API 请求模块”对应前端 `web/api.js` 的请求封装；调用方向为“采购页面 → API 请求模块 → 后端路由”，页面到请求模块的连线标明“调用请求函数”。

默认条件为 `u2` 审批 `r3`，展示“授权允许、金额校验失败”，并标出不进入事务、审计和回执的路径。主体、申请与故障选择只用于推演条件，不执行目标工程或改变示例数据；角色筛选只改变阅读范围。

所有场景、步骤绑定和图关系都是人工编排的**模拟分析结果**，没有运行 CodeCartia 分析器。源码来自 [可运行采购示例](../../examples/purchase-demo/README.md)，文件内容、行范围与指纹均可核对。业务描述与源码事实分别保留证据类型；示例公开功能测试不计入 CodeCartia 的 BS/AP 或深度分析验收。

## 实际文件

```text
prototype/
├─ index.html              # 唯一 HTML 成品，数据与源码已内嵌
├─ demo-data.json          # 生成的完整演示快照
├─ demo-model.json         # 人工编排的业务闭环、实现映射、生命周期、矩阵与诊断
├─ reader.template.mjs     # 可编辑的阅读页面源码模板
├─ build.mjs               # 验证证据并生成离线 HTML
├─ verify.mjs              # 业务结果与内存 DOM 交互回归验证
└─ README.md               # 本说明
```

## 推荐核对路径

1. 在业务总览查看同一申请的 `DRAFT → SUBMITTED → APPROVED` 状态依赖，进入相应转换的业务步骤。提交和审批分别由用户发起，状态依赖不表示提交函数自动调用审批；读取是独立查询。
2. 打开审批场景，查看默认 `u2 + r3` 如何经过身份、对象、授权、状态和金额检查，最终返回金额超限错误并保持 `SUBMITTED`。
3. 切换到 `u2 + r2`，比较正常、审计失败、事务提交失败和回执失败的分支。状态更新与审计必须一起提交；回执失败发生在提交之后，保留 `APPROVED` 和审计。
4. 选择具体业务规则或处理节点，查看它的实现职责、对应调用和精确源码片段，进入代码地图定位；从代码节点或关系反查同一业务规则与步骤。
5. 查看读取场景的实际返回结构，以及共享仓储、审计在不同场景中的职责；导出当前阅读位置、条件、业务路径与实现映射。

## 自定义与生成

1. 业务节点、条件边、连续结果路径、具体实现映射和状态依赖在 `demo-model.json` 中维护，始终保留 `origin: mock`。调用边与业务流程边分别表达，不按共享代码或图连通性补出业务顺序。
2. 页面样式和交互在 `reader.template.mjs` 中维护；它是源码模板，成品阅读入口为 `index.html`。
3. 示例源码改动后，在项目根目录执行 `pnpm --dir examples/purchase-demo evidence`，更新证据位置和文件指纹。
4. 执行 `node docs/prototype/build.mjs` 生成新成品，需 Node.js 20 或更新版本，无第三方依赖；追加 `--check` 只校验，不写成品。生成器只读取示例、证据索引和模拟模型，不运行示例服务或分析器。

生成器检查来源文件和指纹、证据行范围、业务与代码引用、场景/步骤归属、路径连续性及结果终点、生命周期转换、节点边界与重叠、模拟来源标记、内嵌脚本语法和数据标记。细分源码片段来自人工指定的真实位置，并核对文件指纹和片段内容；它们不代表分析器自动提取。

生成后在项目根目录执行 `node docs/prototype/verify.mjs`。该脚本对照独立示例实例的实际业务结果，并在纯内存 DOM 中执行成品脚本，验证分支选择、具体规则与代码的双向定位、往返导航和导出；不启动浏览器或 HTTP 服务，不安装依赖，不改写成品。验证通过仅表示此模拟原型的结果与交互符合检查，不能计入 CodeCartia 分析验收，也不能替代浏览器的视觉与布局检查。

当前 12 组原型回归与 65 个真实示例结果对照已执行通过，包括故障选择后的完整路径高亮、金额失败优先于事务故障、步骤切换后的地图定位，以及生命周期入口定位到真正的事务提交。采购示例的 24 项功能测试也已通过。浏览器直接读取本地文件受当前工具安全策略限制，本次未完成浏览器视觉检查。

配套示例除 B0 运行路径外，另有未引用声明与可被运行时覆盖的内存回执目的地两项诊断扩展。它们不改变 B0 授权，也不构成新的已识别业务。显示的状态效果限定为示例内存事务；回执记录不能证明外部通知已送达。
