本文件建立 47 条稳定需求 ID `REQ01`–`REQ47` 与 24 个既有验收编号的映射。REQ 是追踪单元，不替代逐适配器、版本、输入条件与能力组合的准入单元；新增或拆分需求时追加 ID，保留旧 ID 的关系与理由，不按表格顺序重新编号。

所有 REQ 都由 M1-01 登记；表中「M1 工作包」为需要承接契约、原型、细表或评估工作的包。责任角色表示职责分工，不表示已有人员到岗、子代理已分派或实现已开展。具体负责人及任务状态进入 [M1 任务清单](../progress/M1-任务清单.md)。独立真值/评估角色须遵守项目家族和保留集隔离，不能将保留源码或标注提供给开发、调参或规则生成角色。

范围细化分别对齐[语言框架与输入覆盖清单](../capabilities/M1-语言框架与输入覆盖清单.md)、[业务与授权覆盖清单](../capabilities/M1-业务与授权覆盖清单.md)；具体版本、平台、模式、预算、选型、样本与门槛进入[待决策清单](../decisions/M1-待决策清单.md)。本文件不自行填写这些待冻结参数，也不将尚未决定的组合宣布为支持。

下表中的「未实施／未验收」指目标功能与实际验证；需求追踪文档已建立不改变这一状态。设计修订、规格存在、单条原型成绩和产品通过成绩必须分别记录。

已确认的组织原则是以“业务场景 → 步骤/动作 → 业务对象/业务规则”为主线；在每一步附业务参与者、实际系统角色映射、授权条件、资源/数据范围、入口与检查点。角色视图仅用于跨场景反查和筛选同一组关系，不是并列功能主线。角色/权限/策略仍为可复用独立实体，不强制一角色一场景；关系保留各场景及入口条件。未关联业务的权限声明留存证据和未关联/待核实状态，不生成业务来补齐；无角色、未发现检查不能推成匿名允许。独立权限真值和准入用于评价步骤授权关系与条件结论，继续与业务成功/状态规则区分。
