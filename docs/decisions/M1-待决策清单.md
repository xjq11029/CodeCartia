## 1. 已确认事项

已确认的产品形态为 CLI＋本地 Web；首版所有目标语言分别达到深度分析，业务场景理解及场景步骤中的角色/授权关联属于首版目标，跨项目规则闭环需独立项目验证和回退；核心验收采用自动静态结果，AI 与人工结果分别报告。项目使用 MIT，前端/JS 工作区使用 pnpm。以上事项沿用设计与工程安排，不作为新的待选择项。

本次进一步确认产品按“业务场景 → 步骤/动作 → 业务对象/业务规则”组织，每步附业务参与者、实际角色映射、授权条件、资源/数据范围、入口与检查点。角色视图只跨场景反查和筛选同一关系；角色/权限/策略保留可复用独立实体，不强制一角色一场景，不混合场景或入口条件。未关联声明留存证据及待核实状态，不补造业务；无角色/未发现检查不等匿名允许，授权不等业务成功或状态规则成立。这些是已确认原则，D05/D06/D08/D09 仅细化实现模式、度量及阅读，不再选择是否采用该主线。

本清单将尚未确定的细节登记到责任角色和最迟阶段。M1-01 可先完成追踪整理；冻结支持范围、验收承诺或产品取舍前，向用户提供真实证据、具体备选和推荐项。未决不等于否定首版承诺，不能静默删减需求或以“不适用”隐藏困难。

## 3. 决策记录格式与进入条件

后续每项形成独立决定时记录：

1. 决策 ID、问题、需求来源、受影响 LC/BC/AC/REQ 条目与工作包。
2. 实验输入指纹、探索版本、环境、步骤、预期/实际、耗时/内存、失败边界与报告位置。
3. 具体备选、推荐项与依据，未验证的组合及其阶段影响。
4. 需要用户确认的范围/验收/产品取舍、确认内容与时间；常规内部实现按已确定契约执行。
5. 采纳的版本/边界/预算/门槛、剩余风险和适用期限，后续变更影响与重验范围。

目前尚无以上决定的实测报告。先形成证据，再提交具体选择；时间经过、任务派发或缺少用户回复均不等于采纳待决策项。
