# D12 并发分析与当前快照

> 日期：2026-11-10｜状态：用户已确认产品行为；协议与存储实现按下述要求验证

## 决定与依据

同一工作区发布范围内，以最后发起的分析任务决定当前结果，其他任务的有效结果保留历史。用户在本次设计复审修复中明确选择此项；没有选择“每套分析规则各自维护一个当前结果”。

解决的问题是：同一源码与编译配置分别用规则组合 A/B 发起请求，后请求 B 先完成，先请求 A 后完成时，不能让 A 把界面切回较早选择。输入版本核验与单 attempt 取消锁都不能独立解决这个跨请求竞态。

## 约束

- 发布范围由宿主登记的 publicationSlotId 标识，包含工作区和分析配置范围；规则组合或分析器版本变化不会隐式创建另一个 slot 来绕过顺序。
- 新请求在登记时原子递增并持久化 requestGeneration；latestRequestedGeneration 不依赖完成时间或 worker 时间戳。相同请求重发幂等，用户发起的重试登记为新请求。
- 发布时在同一原子操作内检查 slot、最新世代、任务发布资格、冻结输入/配置一致性，并切换当前快照及其图/矩阵/反查等投影。先检查后另行无条件写指针不合格。
- 旧请求完成可以保存可追溯的历史快照，但不能自动成为 current。最新请求取消、失败或仅产生 partial 时，世代不倒退、不自动启用更早请求；原已发布结果保留，并同时展示最新请求失败/取消/部分状态及旧结果的新鲜度。
- 恢复过程必须保留 latestRequestedGeneration、请求登记与当前快照指针的一致性；记录不完整时停止自动发布并诊断，不根据残留 worker 的完成次序猜测。
- 其他 slot 独立推进。显式查看历史只改变阅读位置；若需把某历史配置重新用于当前分析，应登记新请求。

这些约束不改变 worker 已封存的执行终态。执行成功、历史结果保存成功与更新 current 成功分别记录。

## 验证与影响

关联 R12、REQ21/22/35，落入 M1-02/03/07/08、M2 快照实现。至少验证 A/B 乱序完成、最新请求取消/失败、重复请求、独立 slot、比较与切换之间出现新请求、恢复后迟到旧任务。

[契约与参考模型](../../examples/prototypes/contracts/README.md)验证最小语义；完整 worker、真实数据库事务、多进程并发和崩溃恢复仍须在 M1-08/M2 单独运行，不能由内存模型测试代替。相应事实、版本字段与发布状态以[资源快照契约](../contracts/M1-资源快照与规则组合契约.md)和[worker 协议](../contracts/M1-worker与扩展协议.md)为准。
