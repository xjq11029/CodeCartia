# D13 初版语言验证范围

> 日期：2026-11-12｜状态：用户已确认｜适用：初版设计、M1–M6 验证与发布范围

## 1. 决定与依据

用户要求减少当前需安装的环境，初版先不验证 Java、C++ 等尚未具备完整环境的语言；在说明 C# 仅有 Roslyn 局部实验、完整工程验证仍缺现代 .NET SDK 后，用户明确选择：“C# 整体延后，只验证 JS/TS 和 Python”。

[本机环境盘点](../progress/M1-04-环境盘点.md)记录了可复用的 Node/pnpm、TypeScript API 和 Python。Java 有旧 JDK/JRE，C# 有捆绑 runtime/Roslyn 与既有局部实验；这些事实不代表相应完整工程与框架验证环境已齐。C/C++ 所需语义工具链也尚未准备完整。本决定缩小初版验证范围，不删除已有实验事实，不声称机器上完全没有 Java 或 C# 工具。

## 2. 当前范围

| 阶段 | 语言与相关目标 | 验证要求 |
|---|---|---|
| 初版 | JS/TS：原生 JavaScript、Vue、React、Node.js、Next.js；相关 JSX/TSX、HTML 与配置输入 | 仍分别验证语义、有限数据流、适用框架、跨工程关系与源码依据；框架版本、依赖和模式需按样例冻结 |
| 初版 | Python 及设计列明的适用框架 | 仍验证作用域、导入、调用、有限传播、注册与证据；已有解释器/AST 环境不等于完整分析通过 |
| 后续 | Java、C#、C、C++ | 专属语义、项目加载、框架、平台打包与完整链路验证整体延后；Spring Boot、ASP.NET Core、JDT/Roslyn/Clang 的对应实测随语言延后 |

首版复用现有 JS/TS、Python 环境，项目依赖按具体样例准备；不以安装 JDK、现代 .NET SDK、Clang/MSVC、CMake/Ninja 或多语言容器作为初版前置条件。Ubuntu/Docker 的已有核对与安装预览保留，后续容器准备不阻塞本次范围内验证。

## 3. 对验收与设计的影响

- M1/G1 的真实语言事实核对、传播与业务/授权模式表、环境实验，以及 M3/G3、M6/G6 的语言准入均限定为上述初版范围。延后项明确登记为“后续验证”，不纳入初版必需项、分数分母或通过数量。
- 初版各适配器仍需分别通过深度验收；范围内缺依赖、缺样本、超限或未解析按原质量口径报告，不能用本决定掩盖漏项，也不能将暂缓记成验收通过。
- 混合工程包含延后语言时，实际分析结果仍须报告未支持范围和跨边界缺口；不能因这些语言不参加初版准入，就将整个工作区或相关完整链路标为分析完成。
- HTTP、WebSocket、进程、文件及公共资源关联在 JS/TS、Python 范围内继续验证。FFI 首版验证 Node/Python 调用侧声明及可读库元数据边界；JNI、P/Invoke，以及依赖延后语言的完整原生实现链路留待后续。
- 统一事实/证据模型、worker 协议及语言扩展位置保留。公共契约、快照/恢复、输入隔离、渲染、业务步骤授权、跨项目规则闭环和独立质量门槛不因此减少；与延后语言专属的坐标、宏、程序集/项目加载变体后续补验。
- 已完成的 C# 局部实验及旧范围下的复核结论按历史保留。新范围不自动使 M1/G1 通过，不改变产品尚未实现的状态，也不冻结框架版本、预算、数值门槛或平台组合。

## 4. 后续恢复验证

准备某个后续版本时，先确认纳入的语言、框架、必要环境和样例，再更新覆盖清单与该版本门槛；不会因后来装上某个工具而自动扩大初版范围。恢复后仍需取得真实语义事实、验证只读项目加载、形成模式与独立基准，并按同等深度标准通过验收后才能声明支持。
