## 2. 公共引用与分层约束

本主题所有记录使用公共 `schemaVersion`，并依[统一图与证据契约](M1-统一图与证据契约.md)引用身份、证据、来源与完整性。作用域至少明确 `projectId`、`environmentId`、`configId`、`entryContextId` 的适用性；不适用的入口上下文明确标注，不把缺失值当作全局通配。涉及条件时引用 `symbolId`、`valueVersionId`、`contextId`，不按变量名合并不同绑定值。

关系的 `resolution = confirmed | candidate | conflict | unresolved` 与完整性分列。查询执行结果、配置有效性、快照发布状态和资源是否同一是不同概念，不能全部写进 `resolution`。例如当前输入范围完整但未找到某模块，与输入缺失导致无法完成模块查询分别记录；已确认的局部读取关系也不保证整条业务链完整。

区分四层：目标工程原始事实、各规则独立推导、规则组合合并结果、AI/人工覆盖及其派生结果。目标工程的授权组合/默认效果描述目标实现；本契约的规则优先级/覆盖描述 CodeCartia 的识别执行，二者不得相互代用。

| `id`、`inputId`、`scope` | `id` 是读取/展示登记身份，供公共 Evidence 的 `accessRegistrationId` 引用；`inputId` 指实际输入，供 SourceSpan 等引用。同文件在多个配置下的使用分别登记 |
| `purpose` | 业务源码、静态配置、必要语义输入、可选文档/测试、授权策略或运行观察；独立基准真值不得登记成分析输入 |
| `registeredRootId`、`requestedPath`、`resolvedPath` | 登记根、请求路径和解析后路径；路径检查采用对应平台语义并处理符号链接，不能使用字符串前缀判断包含关系 |
| `origin`、`evidenceIds` | 来源、已有生成产物/外部输入标识、登记依据；证据结构引用公共契约 |
| `inputFingerprint`、`observedState` | 内容与所需元数据指纹；与公共证据和 SourceSpan 的输入版本一致。存在、缺失、拒绝、不可读分别保存，未知指纹不能写成空文件指纹 |
| `readPolicyRef`、`indexPolicyRef` | 只读语义读取与业务索引范围独立；索引排除不扩大或缩小读取登记 |
| `displayPolicyRef` | 可提供证据的类型、范围与可见权限；读取许可不自动授予 Web 浏览许可 |

输入登记只授权在明确范围内只读取证。源码里的路径、命令、导入、项目配置和分析规则均不能自行新增读取根或执行能力。编译 command 作为数据处理，参数里的插件或任意程序能力须在后续只读工具链验证中处理；不能通过执行构建、导入 Python 模块或求值配置来补齐缺失事实。

### 3.2 证据展示边界接口

证据请求至少传入 `evidenceId`、`snapshotId`、请求范围与会话上下文。服务重新检查证据登记、当前会话可访问工程、允许片段及对应根边界；返回内容带快照/指纹和范围，不接受正文提供的任意文件路径。外部语义输入只能由登记证据 ID 提供受限内容；Web 通用文件接口仍限业务根。

内容记录保留内容来源、内容类型、允许展示上下文和受控证据链接。源码、名称、文档、配置、AI/人工文字均为不可信数据；默认文本展示，富文本、URL、SVG/图标签和 HTML 嵌入数据按各自上下文处理，不能直接拼成可执行结构。声明来源可信或分析结果已确认不改变这条边界。

本文件只规定输入/输出接口约束。渲染器选型、具体允许列表、远程资源策略、会话鉴权实现及 Web/HTML/SVG 各上下文反例由 M1-08 与 M1-07 验证，M1-09 冻结；不以本草案宣称渲染或权限实现安全通过。

## 4. 运行资源身份

### 4.1 ResourceIdentity 草案字段

| 记录 | 字段及约束 |
|---|---|
| 进程上下文 | `processContextId`、`serviceId`、`launchEvidenceIds`、`scope`、`fileSpaceId`、工作目录原始值及解析结果、可证明的空间继承；服务名或部署环境名不单独证明运行空间 |
| 文件空间 | `fileSpaceId`、主机/容器/文件系统空间类型、明确空间身份依据、配置指纹；未知空间单独记录，不给多个未知空间同一个默认 ID |
| 文件访问 | `accessId`、所属进程、读写/路径表达式、`originalPath`、条件、证据；原始访问事实与可归一的资源身份分别保存 |
| 文件资源 | `resourceId`、空间 ID 或明确共享资源 ID、空间/卷内规范化路径、路径语义配置、解析依赖与结果；路径大小写、分隔符和卷名按选定平台/空间语义处理 |
| 挂载映射 | `mappingId`、空间及挂载前缀、共享资源 ID、卷内前缀、映射方向/适用范围、证据与指纹；只在映射覆盖访问路径时应用 |
| 消息资源 | `resourceId`、broker 身份及其映射证据、命名空间/虚拟主机、通道类型/原始名称、必要绑定规则与版本/配置；参与服务保留在发布/订阅关系中 |
| 其他协议资源 | 服务/库/协议空间、可取得的目标和绑定依据、适用平台/环境及不透明边界；不能套文件路径身份模型推断所有 FFI、WS 或 RPC |

`resourceId` 表达已取得证据支持的资源身份，不表示某次运行的文件值或消息实例。源码文件身份、运行文件资源身份和该资源的值/版本身份分别保留；同一资源的两次读写不会自动组成同一次数据传递。

### 4.2 解析与未知判定

文件访问先确定所属空间和路径语义。已知空间的绝对路径可直接在该空间解析，不要求工作目录或共享挂载；相对路径必须结合所属进程有据的工作目录。跨空间关联只有在明确共享映射或等价空间依据覆盖两端访问时成立，同空间关联不要求跨空间映射。

共享映射将本地挂载路径转为共享资源和卷内路径，保留转换链。路径归一不能隐含“同名卷即同一卷”或跳过平台规则；无法确认路径表达式或映射覆盖时保留未知原因。必要输入、配置、路径规范化规则和匹配/排除证据均进入解析依赖。

消息资源按 broker 与其命名空间、通道及必要绑定规则核对。名称相同但空间不同不能相连；不同服务连接同一资源时共享资源 ID，不拆资源也不合并各服务主体。生产者、传输身份、下游有效主体由业务授权契约分别描述，资源匹配不能授权身份继承。

## 5. 查询观察与集合依赖

### 5.1 QueryObservation / ObservedCollection 草案字段

| 记录 | 必要字段与约束 |
|---|---|
| 查询观察 | `queryId`、`queryKind`、结构化 `queryKey`、`scope`、搜索根/范围、解析优先级及配置、冻结输入引用、观察结果指纹、完整性、诊断与派生消费者 |
| 查询结果 | `outcome` 区分找到、未找到、歧义、输入不足与读取拒绝；保存完整候选集合引用、选定/排除依据。查询“未找到”不证明项目全局不存在目标 |
| 集合观察 | `collectionId`、集合类型、作用域、成员身份/指纹、成员范围、顺序是否有语义、优先级/配置和集合指纹；空集合与不可观察分别记录 |
| 有序路由集合 | 注册/挂载位置、成员身份、框架版本、有效注册顺序/优先级、启用条件和转交条件；实际有语义顺序进入指纹，不按端点名排序抹除 |
| 派生依赖 | 输入/集合 → 查询 → 事实/摘要 → 跨工程资源/分发 → 场景/步骤授权 → 解释/矩阵/反查/导出；记录失败查询、未关联查询和排除候选的依据 |

所有成功和失败查询均登记其所观察的范围、配置、集合与依赖。选定一个目标后不能只订阅该目标文件；新增第二候选、搜索优先级变化或原缺失文件出现都可能改变结论。集合没有稳定指纹或输入范围未核验时，完整性显式保留缺口。

目录成员、源码根、导出表、路由注册、依赖/生成输入、资源映射、角色/策略与场景绑定集合均可成为查询依赖。路由顺序、策略顺序、有效主体和对象值版本属于语义数据，不可作为“输出顺序”忽略。

## 6. 冻结、发布、失效与等价

### 6.1 Snapshot 草案字段

| 字段 | 内容与约束 |
|---|---|
| `snapshotId`、`schemaVersion`、`scope` | 快照身份、契约版本和选定工程/配置；快照 ID 不代替输入指纹 |
| `inputManifestRef` | 原始输入、外部/生成语义输入、缺失观察、配置/集合及其指纹；记录输入一致性核验结果 |
| `identityRegistryRef` | 逻辑身份登记与已接受匹配历史的版本/指纹、来源及作用范围；增量与全量重建使用同一身份登记，不要求仅凭当前源码重新猜出旧移动历史 |
| `analysisProfileId`、`analyzerVersions`、`effectiveRuleSetId` | 分析配置记录引用、各分析器/解释器版本与实际启用组合，不能只存名义最新版本 |
| `patternTableRefs`、`budgetProfileId` | 传播及业务/授权模式表、计算预算版本/指纹；预算数值待 M1-05/10 测量与冻结 |
| `overlayRefs`、`explanationConfigRefs` | 人工覆盖版本/范围、AI 模型/提示/输入证据指纹；自动核心身份与辅助视图身份分别可重建 |
| `resultRefs`、`dependencyGraphRef` | 原始/派生实体、关系、证据、查询、集合、业务绑定、诊断和来源依赖 |
| `executionState`、`publicationState` | 执行与发布分别记录；运行中、取消、失败或部分结果不自动成为已发布完整结果 |
| `completeness`、`previousPublishedSnapshotId` | 公共完整性与上一个已发布快照；旧结果过期说明和新任务中间结果不混成当前依据 |

`analysisProfileId` 指向版本化 AnalysisProfile，至少保存分析器/解释器版本、有效规则组合、来源视图、模式表和预算记录及其指纹；字段与快照对应配置一致，未知预算不能写成无限。`budgetProfileId` 可被公共截断诊断引用，未形成预算配置时明确记录未决状态及影响，不伪造已冻结值。

冻结要求同一任务内必要输入和配置版本一致。期间发现变化时重试该任务或将变更纳入下一任务；无法核验一致性的结果只报告缺口，不发布为完整快照。读取被拒绝、缺失输入和预算截断的影响保留到对应结果，不能靠任务正常退出消除完整性缺口。

发布先保存新版本结果及依赖，再整体切换该范围内的可见快照。原子替换涵盖主图、场景步骤、授权绑定、解释、矩阵、角色反查及诊断，不能让查询同时读到不同版本。具体存储事务和恢复实现由 M1-08 验证，本草案不选择 SQLite 驱动或存储方案。

取消、超时、崩溃或任务失败不能替换原完整结果。允许提供明确标注的中间/部分结果供诊断；保留旧已发布快照，输入变化时标明旧证据与位置过期，不能将其显示为当前源码依据。人工注释保留并绑定原快照，匹配到新事实前不静默迁移为当前确认。

### 6.2 失效传播与回退

输入/配置/有序集合变化沿查询、事实、摘要和派生关系传播。精确影响范围未知时扩大到相关工程/配置，必要时全量重建；重算前相关结果过期，不复用可能失效的确认。文件移动/重命名保留显式身份匹配，删除须删除或撤去旧实体的当前引用。

角色/策略声明、挂载、顺序/默认效果、数据过滤、有效主体映射、业务文档和场景组织变化，均影响相应条件与解释。场景归并/拆分、入口/步骤解绑、新增关联须同步更新绑定、角色反查与未关联诊断；保留其他场景仍有独立证据支持的共享原始事实。

规则组合停用、定向覆盖变动或回退改变组合指纹及其缓存键，重算受影响输出和后续推导。旧版本缓存只能在其冻结输入、配置、组合、模式表与预算均匹配时使用；不能把标签改回旧版本而继续展示新版本结论。人工覆盖在原始证据变化后重新核对作用范围，无法核验时标为过期。

### 6.3 增量与全量等价

比较前冻结相同输入、配置、身份登记/匹配历史、分析器/解释器、有效规则组合、模式表、预算和所比较来源层。历史由 `identityRegistryRef` 明确传入，是用于身份连续的分析元数据，不包含评估答案、业务事实或授权真值，也不代替当前证据；它不作为当前源码全量扫描可独自产生的结果，新匹配记录在同一历史基准下比较。身份登记保留来源，人工/AI 指定的匹配及其派生仍归相应覆盖层，不能进入纯自动基线。比较范围包括实体身份和匹配记录、关系类型/解析状态、候选/排除理由、条件及绑定值版本、证据/推导、来源、诊断、完整性、资源身份、实际分发/检查链、场景归属、步骤授权和反查结果。

允许忽略快照 ID、时间戳及无语义输出顺序。不得忽略注册/策略顺序、主体变化、条件、未知原因、被排除路径、未关联声明、过期证据或部分结果。SN01/SN02/SN05 和 RL04 的每一步均独立与该输入全量重建比较，不能只对最终恢复状态比较一次。

## 7. 来源与有效识别规则组合

### 7.1 来源继承与覆盖层

所有原始事实、每条规则独立推导、合并结论及辅助覆盖引用公共来源记录，保留完整输入事实与规则链。使用分析时 AI 或人工事实的后续推导继承辅助来源；最后一步使用静态程序不使链条变为纯自动。

已通过独立验证并版本化固化的识别规则，可在不调用 AI 的自动分析中使用；规则生成来源仍留存。这与把分析时 AI 线索直接当作自动事实不同。质量报告分别取自动核心、AI 辅助和人工调整结果，运行观察另作补充；基准人工真值不进入任何分析来源层。

人工覆盖保存原始自动结果、作者/理由、补边/删边/选定候选等动作、受影响身份/范围、证据与适用快照。覆盖与其派生结果可查看，不能改写底层自动事实或用人工指定结论改善自动成绩。

### 7.2 EffectiveRuleSet / OverrideDeclaration 草案字段

| 记录 | 字段与约束 |
|---|---|
| 规则包 | 包 ID、不可变版本/内容指纹、父版本、语言/框架/配置范围、依赖、来源和独立验证报告 |
| 有效规则组合 | `effectiveRuleSetId`、组合指纹、实际包/规则 ID 与版本、启用状态、优先级、适用范围、依赖/阶段、解释器版本、显式覆盖及其验证状态 |
| 独立规则输出 | 原始输入事实引用、输出关系/字段、上下文和条件、规则与组合身份、推导证据、来源/完整性；不能原位修改其他规则输出 |
| 定向覆盖声明 | `overrideId`、覆盖规则、目标规则/输出字段、作用域与条件、明确启用状态、可核验依据、覆盖前后结果引用与验证诊断 |
| 合并/冲突记录 | 等价或兼容性依据、全部来源、条件/上下文、互斥关系约束、冲突双方输出和覆盖适用性；未验证的等价不得静默去重 |

同有效组合和配置按冻结阶段及依赖执行。同阶段规则读取同一输入版本，汇总后统一合并；不以数组输入顺序、包加载顺序或 worker 完成顺序决定事实真假。阶段间依赖及有语义顺序进入组合指纹。迭代方式和预算由 M1-05 冻结，未收敛或超限时保留截断/未知，不宣称完整确认。

### 7.3 合并、冲突与定向覆盖

兼容结论累加；同作用域/上下文/条件下的同一结论可去重，但保留全部来源。不同条件分别保存；类型允许的合法多态候选不构成互斥冲突。判断依赖公共关系约束和有据的条件兼容性；无法证明等价的条件不能直接合并。

同上下文中，条件可能重叠且按关系约束互斥的输出记为冲突并保留双方。不因项目/工作区/公共层级或更高优先级自动确认一方。没有明确互斥关系约束时，不能仅因目标不同虚构冲突；无法判定条件重叠时保留候选与待核实原因，对具有明确互斥约束的输出记录潜在冲突，不能凭未知条件排除一方或静默选定。

定向覆盖只在明确声明的目标规则/输出字段、范围和条件内生效；需明确启用并有可核验依据，保存被覆盖派生结果、原因和来源。即使覆盖生效，底层源码/语义事实仍留存。覆盖不存在目标、循环或相互矛盾的覆盖/依赖均报配置诊断，受影响结果不能形成无提示的完整确认；优先级不能代替覆盖声明。
