# M1 调用上下文与 HTTP 分发契约

> 草案版本：0.2｜schemaVersion：`0.2-draft`｜日期：2026-11-10｜工作包：M1-02
>
> 依据：设计 v0.6 §6.3、§7.1、§8.2；推进 v0.4 §4.2；R01/R09、BS01/BS02/BS03、AP04/AP05。
> 状态：供原型核对的文档草案，未执行分析验证；框架版本、传播与分发模式、条件求解及预算尚未冻结。

本契约回答两个问题：共享实现如何按每个调用入口分别绑定，HTTP 地址匹配如何有据进入处理链。公共身份、证据、来源和完整性遵循[统一图与证据契约](M1-统一图与证据契约.md)；[业务场景与步骤授权契约](M1-业务场景与步骤授权契约.md)仅沿兼容且可核实的路径关联步骤与检查。

## 1. 先确定最小正反例

下表均为后续原型的指定输入和预期，当前没有执行结果。局部例号只用于本文定位，不新增 R/BS/AP 验收组；路径、常量及函数名均为合成输入，不成为产品默认行为。

### 1.1 调用与条件

| 局部例 / 来源 | 最小输入 | 应保留的结果 | 必须排除的结论 |
|---|---|---|---|
| C1 / R01 正例及串线反例 | A 调用 `request('/users')`，B 调用 `request('/orders')`；包装器执行 `fetch(path)` | A/B 有不同调用点和摘要实例，分别绑定各自 URL；包装器源码实体可共享 | A 到 `/orders` 或 B 到 `/users` 的确认链路 |
| C2 / R01 多层与返回 | A/B 分别调用 `outer(p)`；`outer` 返回 `inner(p)` 的结果，`inner` 返回 `fetch(p)` 的结果 | 每层实参→形参、返回→调用结果保留调用与返回配对；不能从另一实例取返回值 | 同名形参或返回槽汇总后分发给所有调用者 |
| C3 / R01 互斥分支 | 在同一符号、值版本及上下文下，上游路径要求 `flag == true`，下游要求 `flag == false` | 保留局部事实，完整路径标为条件矛盾并给出依据 | 因单边均存在而确认完整路径 |
| C4 / R01 同名不同绑定 | 两个函数各有 `flag`，或同一变量被重新赋值后产生新值版本 | 先判断绑定关系；不能把不同符号/值版本的两条件视为同一个变量的矛盾 | 仅凭文本相同排除合法路径，或认定两条件必然同时成立 |
| C5 / R01、S01 未知与超限 | 必要函数摘要、别名或回调目标缺失；独立变体超过待测展开预算 | 保存已取得事实、候选、截断位置和原因；完整链路未知 | 将未展开目标当作不存在，或以局部完整冒充链路完整 |
| C6 / BS01、AP04 共享实现 | HTTP 入口与消息入口调用同一处理器；各有独立输入及主体取得证据 | 共享处理器实体，保留两个入口上下文与逐路径身份/资源绑定 | 因共享函数互相继承参数、认证、角色或授权结论 |
| C7 / BS02 对象与版本 | 输入读取对象 X，却将状态写到对象 Y；另有别名无法确定的变体 | X/Y 绑定及版本分开；同一性未证实则状态转换未知 | 将 X 的读取与 Y 的写入拼成 X 的状态转换 |

### 1.2 HTTP 地址候选与分发

H1–H8 使用明确提供的合成路由注册、挂载和控制转移语义；不由例子声明任何真实框架版本已支持。真实框架分别在 M1-04/10 核对对应版本的映射、优先级和转交语义。

| 局部例 / 来源 | 最小输入 | 应保留的结果 | 必须排除的结论 |
|---|---|---|---|
| H1 / R09 同地址遮蔽 | 同一服务/方法下，先注册 R1 后注册 R2，均匹配 `/item/:id`；R1 只在 `id == '0'` 时跳过当前路由，其他分支响应并返回且无后续转交 | `/item/5` 的地址候选含 R1/R2，条件化可达路径只进入 R1；R2 的排除理由为遮蔽/未转交；`/item/0` 才进入 R2 | 把两个地址候选都接入确认处理链，或把 R2 检查套到 `/item/5` |
| H2 / R09 显式继续 | 独立变体提供响应写入后显式继续的控制事实 | 响应效果与转交分别保存，继续分支依实际语义展开，可能产生后续错误 | 单凭响应 API 名称截断控制流 |
| H3 / R09 错误分支 | R1 正常路径结束，错误分支显式转入已挂载错误处理器 E | 正常路径与错误路径分别保存条件和有序步骤；仅错误路径关联 E | 将 E 当作每次正常请求必经处理器 |
| H4 / R09 模板与约束 | 精确路径与参数模板重叠；输入给出方法、参数/请求头/媒体类型限制及实际优先级 | 按对应语义先形成候选，再判定条件化分发和排除理由 | 只按字符串相等或统一取第一条处理所有框架 |
| H5 / R09 未知 | 保持端点声明，但移除必要挂载/顺序/控制转移语义；另有预算超限变体 | 地址候选仍可报告；可达性及依赖它的完整链路、步骤授权保持未知，指明缺失位置 | 以“地址唯一”代替分发证据；或将未知理解为不可达/未授权 |
| H6 / R09、R02 只变顺序 | 在 H1 基础上只交换 R1/R2 注册顺序，集合成员及源码其余部分不变 | 有语义的注册集合指纹变化；重算可达处理链及场景/权限；增量与同输入全量等价 | 因端点无序集合未变而复用原确认结果 |
| H7 / R09、BS03 挂载与开关 | 声明存在但未挂载，或挂载在当前关闭的条件分支中 | 保留声明与条件注册；当前配置不作为已启用入口，缺证据部分保留未知 | 从函数/注解存在推出入口已生效 |
| H8 / R09、AP04 多入口 | 处理器另由消息入口调用，HTTP 上游检查仅覆盖 HTTP 分发路径 | 各入口分别形成检查覆盖与上下文；消息入口缺身份依据则未知 | HTTP 受保护就判定共享处理器的全部入口同样受保护 |

## 2. 公共引用与调用字段

以下为字段提议，不是已实现接口。每个具名版本记录持有公共 FactRef；逻辑实体端点使用 EntityRef，摘要/实例/路径、证据、条件和推导依赖使用完整 FactRef，按公共 §2.1 精确解析。每条关系仍使用公共 `Relation`，单独记录 `resolution = confirmed / candidate / conflict / unresolved`、`targetMode = exact / candidateSet / unknown`、`targetSetCompleteness = complete / partial / unknown`、`Completeness`、证据与推导引用。解析状态不替代候选集合完整性，`confirmed` 也不证明某次运行已执行该调用。

### 2.1 入口、调用点与摘要实例

| 结构 | 必要字段 | 身份与引用约束 |
|---|---|---|
| `EntryContext` | `id`、入口实体、入口种类、`scope`、输入绑定、初始条件、身份/资源上下文引用、证据 | `scope` 含 `projectId / environmentId / configId / entryContextId`；入口身份与上下文分开，多入口不能仅因最终处理器相同合并上下文 |
| `CallSite` | `id`、所属符号、被调用表达式、实参与调用结果槽、原始位置、证据 | 调用点与被调用符号有独立 ID；位置变化使用公共身份匹配记录，行号不单独作稳定 ID |
| `FunctionSummary` | `id`、被摘要符号及签名、版本/输入指纹、形式参数与返回槽、条件化传播/调用/作用摘要、依赖、完整性 | 摘要表达相对于形参的事实；不把所有调用者实参的并集当成该函数每次执行的事实；重载/泛型等实例语义由对应适配器提供 |
| `InvocationBinding` | `id`、`callSiteRef`、`summaryRef`、`callerContextRef`、`calleeContextRef`、入口上下文、实参/形参配对、返回/结果配对、条件、证据/推导 | 配对项引用 `symbolId / valueVersionId / contextId`，保留接收者/字段/别名等必要绑定；缺必要项时保留未知，不借用其他调用实例填充 |
| `CallContext` | `id`、`entryContextId`、父上下文、调用点、摘要实例绑定、配置、条件、传播模式/预算引用 | `contextId` 区分内部摘要实例；`entryContextId` 指可追踪起始入口。同一静态调用点由不同上游调用进入时仍须按支持模式区分参数实例 |
| `ValueBinding` | `id`、所属符号、值版本、上下文、值/模板或候选、字段路径、别名依据、来源 | 值版本由已支持的赋值/写入/返回事实确定，不能只按变量名或属性名标识；候选值与排除理由可并存 |

所有 `evidenceRefs / derivationRefs / conditionRefs` 及 summaryRef/callSiteRef/callerContextRef/calleeContextRef 均精确引用同一快照内版本；没有指定 revision 不得查找“当前”摘要。保留的 contextId/entryContextId/symbolId/valueVersionId 是绑定和作用域身份，不能单独充当摘要/条件内容的依据。跨工程调用使用明确的两端工程引用与配置映射，不把调用方的工程身份替换成被调方身份。环境或配置跨界须有映射证据，不能自动继承同名环境。

省略参数、默认值、接收者、可变参数、泛型替换、闭包捕获、回调和递归各模式均须在 M1-05 登记适配器前提。公共结构允许表达这些事实，不声明它们已经能被所有语言提取；无法表示或验证的必要绑定必须降低相关推导完整性。

### 2.2 条件与链路组合

| 结构 | 必要字段 | 组合约束 |
|---|---|---|
| `Condition` | 公共 `id / expression / bindings / semanticProfileId / evidenceRefs / evaluation / requiredInputs`；`bindings` 内引用 `symbolId / valueVersionId / contextId`，关联适用配置与完整性 | 常量、比较、逻辑组合与未知项分别表达；每个操作须有支持依据。原始表达式文本供阅读，不能替代绑定后的语义；`evaluation` 是具体赋值下的满足/不满足/未知，与路径相容性分开 |
| `PathConstraint` | 路径条件引用、绑定/替换记录、组合结果、支持/反对证据、缺口 | 对同一绑定值能证明互斥时排除；不同作用域/值版本不自动互斥；条件可能重叠或无法求解时保留未知，不能凭优先级选择 |
| `StaticPath` | `id`、入口上下文、起止实体、按路径次序的关系/绑定引用、条件、调用返回配对、排除路径、来源、完整性 | 内部关系的上下文、参数、对象和返回配对须兼容；完整链路不能由忽略上下文的普通图可达性直接生成 |

条件组合结果提议为 `compatible / contradictory / unknown`：

- `compatible` 表示在声明支持的条件规则及列明前提下，绑定与条件可共同成立；仍需逐条确认必要关系，才形成“在所列条件下可静态关联”的链路。
- `contradictory` 须给出同一绑定值的互斥依据；只排除受该矛盾影响的路径，保留其他候选及局部事实。
- `unknown` 记录未知操作、属性、缺失输入、摘要/别名不完整或超限；不作为允许、拒绝、不可达或不存在的同义词。

候选集合完整但包含合法多态目标时，可确认“这些是静态调用候选”这一关系，使用 `targetMode=candidateSet`、`targetSetCompleteness=complete`；多目标本身不构成 `conflict`，也不能据此选定运行目标。只有所需路径关系、绑定及条件在当前支持范围内可核实，才能确认条件化静态链路；不确定目标的路径分别保留候选与未知原因。静态关联不证明实际时序、事件已发生或异步任务已完成。

## 3. HTTP 字段与分发约束

### 3.1 请求实例、注册与地址候选

| 结构 | 必要字段 | 约束 |
|---|---|---|
| `HttpRequestInstance` | 请求/调用点 ID、调用与入口上下文、服务/环境、方法、URL/baseURL 模板、参数与请求头/媒体类型条件、拦截器/代理/rewrite 推导、证据 | 各调用实例独立绑定；服务解析和 URL 变换依赖实际配置，未知服务或动态值不得直接匹配成唯一端点 |
| `RouteRegistration` | `id`、端点实体、处理器/中间件序列、服务、方法与路径/参数/请求头/媒体类型约束、注册/挂载位置、启用条件、框架/语义版本、顺序或优先级依据、证据 | 端点声明、注册、实际挂载分别有事实；动态顺序或缺失挂载保持未知。顺序来自源码/配置与版本语义，不能使用 worker 到达顺序 |
| `AddressMatch` | 请求实例、候选注册 ID、匹配条件、`matchKind`、匹配/排除依据、查询/候选集合依赖及完整性 | `matchKind` 提议为 `exact / template / ambiguous / unmatched`。匹配只证明地址条件相容，不证明处理器可达；多个候选和未匹配均保存搜索范围 |

头部大小写、路径转义/规范化、可选参数、方法扩展、优先级、嵌套路由和 content negotiation 等规则必须由对应版本的适配器事实明确，不能以公共路径拼接方式强行统一。M1-02 只定义保存位置；M1-04/10 分别验证模式与版本。

### 3.2 条件化分发与控制转移

| 结构 | 必要字段 | 约束 |
|---|---|---|
| `DispatchSemantics` | `id`、框架/适配器及版本、注册/挂载/匹配/优先级规则引用、控制转移映射、来源与验证状态 | 映射描述目标工程实际语义，不使用统一的“所有匹配均可达”或“第一条匹配胜出”；未验证必要语义时分发结论未知 |
| `DispatchStep` | `id`、注册/挂载与处理器引用、请求/上下文、适用条件、响应效果、语言控制流、框架转交、后继及证据 | 响应写入/结束、语言 return/throw、框架继续/跳过/错误转交分别表达；响应 API 本身不代替控制流证据 |
| `DispatchPath` | `id`、请求实例、语义版本、注册集合指纹、按控制路径有序的步骤/转移、完整条件、正常/错误出口、排除候选及理由、来源、完整性 | 只把此路径上可核实的处理器纳入场景与检查覆盖；有语义的顺序不得排序消除；未知部分限制下游结论 |

框架转交可规范化为“继续当前处理链”“跳过当前路由”“离开当前路由器”“进入错误处理”“停止分发”“未知”；每一项都须引用目标框架/版本及控制事实。此词表用于保存结果，不规定任何框架自动拥有全部操作。

“停止分发”需要可核验的控制路径及分发语义，不能仅由发现 `return` 或响应写入推定。语言函数返回如何影响路由器、中间件或异步处理链，由该语义映射解释。响应后仍存在显式转交时保留后继及可能错误分支；不能为让链路看起来正常而删除源码控制事实。

条件化可达路径的推导顺序为：

1. 冻结请求实例及实际服务/配置，按完整地址约束登记匹配候选和搜索依赖。
2. 引用实际注册/挂载事实和有语义的顺序/优先级，实例化处理器输入与路径条件。
3. 按支持且有依据的分发语义展开正常、继续、跳过、停止及错误分支，保存每次控制转移证据。
4. 对沿途绑定与条件做兼容判断；已证实不可达的候选保留排除理由，未知的候选保持未知。
5. 对每条可核实路径连接业务步骤及实际检查；检查须覆盖该入口、有效主体、动作和资源，且在对应条件下执行。

地址候选唯一也不能跳过第 2–4 步。一个可达分支或一个允许检查结果不能代表整个场景对该角色开放。反查和矩阵引用相同 `DispatchPath`、入口与步骤绑定，不能把另一候选处理器的角色或数据范围移入当前路径。无检查的观察只报告扫描范围与缺口，不能由此确认匿名允许。

## 4. 完整性、变化与复现

### 4.1 未知和截断

| 缺口 | 至少记录 | 必须限制的结果 |
|---|---|---|
| 缺摘要、绑定、配置或输入 | 缺失输入/绑定 ID、查询范围、影响的上下文及关系 | 依赖该缺口的调用实例、完整链路、对象状态和授权判断 |
| 未支持条件或分发语义 | 模式/适配器/版本、原始表达式或控制位置、未知原因 | 不能确认该条件下可达/不可达或补齐默认策略 |
| 展开/候选/迭代超限 | 预算配置引用、实际使用量、截断位置、剩余范围 | 保存局部事实与候选；`Completeness.complete=false` 并填入 `truncations`，不得假装穷举 |
| 输入变化或过期 | 旧/新输入指纹、受影响结果、快照及重算状态 | 旧证据仅作为历史引用，不能显示为当前确认依据 |

`Completeness` 复用公共字段 `complete / missingInputs / unsupportedModes / truncations / freshness / affectedScope / diagnosticRefs`。局部事实可在相关分析范围不完整时保持其有据 `confirmed`，但依赖必要缺口的完整链路或确定授权结论须受限。预算数值及超限计分规则属于 D04/D08 和 M1-05/06，不在本草案填默认值；未定义的模式或预算不能成为完整性承诺。

### 4.2 依赖登记与增量对照

调用摘要依赖源码、编译/运行配置、语义输入、解析查询/候选集合、支持模式和有效规则组合；每个实例再依赖调用点、实参/值版本、入口绑定和其引用的摘要。成功查询和失败查询都必须登记搜索范围与集合版本。新增第二候选、缺失模块出现、返回逻辑变化或入口参数变化均可使旧实例失效。

HTTP 查询与路径额外依赖服务映射、代理/rewrite、拦截器、完整注册集合、挂载、启用条件、框架/语义版本、顺序/优先级和控制转移配置。注册集合指纹按有语义的顺序计算，不能仅对端点成员排序后散列；对无语义输出顺序的规范化不能删除真实注册顺序。

变化沿摘要/实例/地址查询/分发路径传播到场景、步骤授权、角色反查、条件矩阵、影响查询与解释。无法确定精确范围时按[资源、快照与规则组合契约](M1-资源快照与规则组合契约.md)扩大重算范围，不能保留可能失效的确认链路。删除入口只撤去受影响绑定，其他入口仍有依据的共享实现或角色/策略事实继续保留。

同一冻结输入、配置、分析器、有效规则组合、支持模式和预算下，增量与全量须在调用候选、上下文、参数/返回配对、条件、地址候选、分发顺序、排除依据、步骤/检查绑定、证据与诊断上等价。比较时先建立版本事实对应，再忽略仅容器身份的快照 ID、时间戳和无语义输出顺序；运行时 FactRef 不得忽略这些精确键。打乱 worker 完成顺序不得改变参数绑定或目标工程的注册顺序；跨发布请求的当前结果选择另受 R12 最新请求世代约束。
