## 2. 公共记录与引用

本草案采用具名记录描述约束，不选定存储引擎、语言接口或线上序列化。后续 worker 协议由 M1-03 定义；任何适配器扩展均不得绕过公共证据与验收。

| 记录 | 作用 / 必要引用 |
|---|---|
| ContractEnvelope | 当前 schema、快照、分析配置及范围；业务对象引用它表达同一分析视图 |
| Entity | 可复用对象的逻辑身份；版本事实单独保存 |
| Relation | 起点、目标或候选集合、类型、条件、证据、推导与解析状态 |
| Evidence | 原始载体、输入指纹与定位；不自行等同于支持某项结论 |
| Derivation | 输出到直接输入、规则/分析器和支持/反对证据的有向依赖 |
| Claim | 一项结构化或文本结论；逐项保留依据、结论类型与状态 |
| Condition | 绑定符号、值版本及上下文的条件表达式与可判定范围 |
| Completeness | 缺输入、未支持、截断、过期与受影响范围；独立于解析状态 |
| Diagnostic | 缺口/冲突/映射失败等具体原因、作用范围和依赖 |
| IdentityMatch | 移动、重命名、归并/拆分的显式匹配依据 |

公共事实指 EntityVersion、Relation、Claim 及其他具备版本内容的主题记录；逻辑 Entity 本身不代表当前版本已经验证。所有参与证明、求值、覆盖、失效或来源校验的引用使用下述 FactRef；跨快照引用只在历史查询中显式使用，不能伪装为当前证据。

公共字段使用 `evidenceRefs`、`derivationRefs`、`conditionRefs`；主题记录中对角色、策略等对象的引用仍必须能解析到具名记录。数组顺序只有被声明为有语义时才参与判定；授权检查顺序、HTTP 注册/控制顺序均有语义，不能作为集合排序抹除。

### 2.1 逻辑实体引用与精确事实引用（R11）

| 引用 / 记录 | 必需字段与语义 |
|---|---|
| EntityRef | `kind=EntityRef/entityKind/id/projectId`；只定位身份登记内的逻辑对象，用于 Relation 的 `sourceRef/targetRefs`、导航和身份连续性，不选择事实版本、不证明该对象已确认 |
| FactRef | `kind/id/revisionId/snapshotId/sourceViewId/scope/layer`；kind 是 EntityVersion、Relation、Evidence、Derivation、Condition 或具名主题记录类型；全部字段共同组成精确引用键 |
| scope | `projectId/environmentId/configId/entryContextId`；未知/不适用沿公共约束显式表达，不以省略字段作为通配；跨工程或跨入口的依赖保留被引用事实的完整 scope |
| layer | `base/rule-output/merged/overlay/runtime`；区分原始事实、独立规则产物、合并结果、辅助覆盖与运行观察，不代替 sourceViewId 或证据 production |
| 版本记录 | 自身持有完整 FactRef 与不可变内容；同键异内容拒绝。同逻辑 ID 的不同 revision 可共存，不能用最大版本、到达先后或数组第一项解析依赖 |

各主题表中的逻辑对象标识与作用域键仍可用 `...Id`；凡表示摘要、绑定、路径、检查、策略内容、查询/集合观察、映射、诊断或其他语义依赖，均须使用 FactRef（字段写作 `...Ref/Refs`，不得传字符串 ID）。`evidenceRefs/conditionRefs/derivationRefs` 的成员也都是 FactRef。EntityRef 不能作为 `inputFactRefs` 的成员；关系依赖实体的版本属性时，另在推导中引用对应 EntityVersion。

下游规则默认读取已完成相应阶段的 `merged` 版本；需要独立规则输出或原始事实时，输入契约明确允许的 layer 并精确引用。合并结果另有自己的 revision，不改写原始版本。来源视图间引用只可由宿主登记的来源视图组合显式允许，例如辅助视图引用冻结自动基线；自动视图禁止读取分析时 AI/人工覆盖及其传递依赖。sourceClosure 按每条 Derivation 的精确输入计算，不能把同结论的独立支持误写成必须全部同时存在的单条推导。

Derivation 使用 `inputFactRefs/outputFactRefs`；前者才是因果输入，后者指向所支持的精确输出版本。`derivationRefs` 是宿主由独立 Derivation 生成的查询投影，**不进入 worker 输出事实的不可变 payload**，不作为该输出的输入，也不参与其内容 revision 的生成；投影单独带版本/指纹。这避免新增支持分支时原位修改同键事实，也避免输出/推导互含内容指纹。因果图只沿“输出版本 → 支持推导 → 输入版本”校验：直接自依赖和同版本间接环拒绝；迭代必须引用先前的明确版本，并具有非循环的基础来源。删除一条 Derivation 只撤销该分支，其他独立分支继续保存；如果有效合并含义改变，创建新 merged revision 并重算消费者，不能重定向旧引用。

`0.2-draft` 不兼容 `0.1-draft` 的 ID-only 事实引用。缺 revision/snapshot/sourceView/scope/layer 的旧记录不能在接收时补“当前版本”；迁移须从旧完整快照和独立推导显式确定唯一版本、记录迁移依据并重新验证，无法唯一确定时拒绝迁移。独立 bootstrap 与原始坐标策略仍保留各自版本。

### 2.2 分析视图包络

| ContractEnvelope 字段 | 必要约束 |
|---|---|
| schemaVersion | `0.2-draft`；所有主题使用同一版本，修改含义须升版或显式迁移 |
| snapshotId | 指向冻结输入、分析器/规则组合、模式与预算的 Snapshot；不是内容正确性的证明 |
| scope | `projectId/environmentId/configId/entryContextId`；调用内部另用 `contextId`。缺失环境/入口不能自动设为任意环境/入口 |
| analysisProfileId | 指向分析器、有效规则组合、来源视图、支持模式及预算记录；不把未知预算填为无限 |
| completeness | 当前记录或输出批次的完整性；字段组只允许整体批次继承，不跨 scope 隐式继承 |

实体声明可能尚无入口，例如先索引策略；此时 `entryContextId` 可明确记“尚未绑定”，不能把它解释为覆盖全部入口。环境/配置未知同样附诊断；独立的已知字段仍可保存。

未知、已知无此项、未扫描是不同情况。空数组仅表示当前记录没有列出成员；查询范围、集合完整性与缺口共同决定是否可解释为“扫描后无成员”。必需字段缺失时拒绝该确认输出或降为带诊断的部分事实，不用空字符串/默认值伪造事实。字段确实不适用时记录原因，不以“不适用”删除首版必需目标。

## 3. 身份与版本

| 对象 / 字段 | 草案身份约束 |
|---|---|
| Entity `id/kind/identityKey` | ID 与显示名分开；identityKey 是带命名空间的可复核组成项，不是单个行号或名称。编码/摘要算法待原型核对 |
| 工程 / 配置 | 工作区内显式工程身份与选定环境/编译配置；目录名相同不等同工程身份 |
| 文件 | 工程 + 已登记源码/语义根 + 文件逻辑身份；路径用于查找，输入指纹用于版本。路径大小写/链接规则来自选定文件空间，不能全局 lowercase |
| 符号 | 文件逻辑身份 + 词法/限定声明锚点 + 可取得签名或区分键；重载、局部同名及匿名声明不能按显示名合并 |
| Relation `id/revisionId` | 逻辑 ID 由类型、起点、调用/声明锚点、scope 与绑定条件等语义键决定；revisionId 随候选集合、证据和状态变化。完整语义键按关系类型登记 |
| 业务场景 / 步骤 | 工程、可追踪入口/绑定范围及语义锚点；名称、连通分量、共享代码不能独自确定归并；详见业务契约 |
| 运行资源 | 资源所属空间与类型等组成，不复用源码文件 ID；详见资源契约 |
| IdentityMatch | `oldEntityRefs/newEntityRefs/kind/evidenceRefs/scope/resolution`；旧新对象使用 EntityRef，一对多/多对一与歧义显式记录。不能把推测匹配当作身份连续 |

移动/重命名后旧版本和匹配记录保留；删除事实使当前视图撤销相应引用。无法可靠匹配时生成新身份，旧注释可保留历史提示或待核实候选，不能无提示绑定到任意新对象。来源证据、候选和派生更新均遵守快照失效契约。

Snapshot 的 `identityRegistryRef` 冻结逻辑身份登记与自动匹配历史；同历史的增量/全量重建使用相同版本，不能要求仅凭当前源码重建旧移动历史。登记只包含身份连续性的分析元数据，不含独立评估答案或替代业务事实。人工/AI 匹配保留独立来源及覆盖层，不进入纯自动身份基线；跨新工作区比较需先按有据语义键对应身份，再单独核对历史。

基础实体至少覆盖工作区、工程、环境、文件、符号、组件、页面、端点、请求、进程、数据库、消息通道、文件资源及外部库；业务实体补充能力、场景、步骤、动作、对象、规则、参与者、主体、角色、权限、策略和检查点。有数据库/外部库身份不表示当前已取得全部内部实现。

关系类型至少覆盖导入、引用、静态调用候选、组件渲染、传参、返回绑定、事件绑定、路由注册、条件分发、依赖注入、发送/处理请求、发布/订阅、文件读写、进程启动和 FFI；业务/授权关系详见主题契约。这里登记设计范围，不宣称对应适配器已实现。

## 4. 关系、条件与完整性

| Relation 字段 | 约束 |
|---|---|
| ref / type / sourceRef | ref 为当前 Relation 的完整 FactRef；sourceRef 为 EntityRef，版本身份、谓词和逻辑起点分别表达 |
| targetMode | `exact/candidateSet/unknown`；不将可能目标解释为运行时选定目标 |
| targetRefs / excludedTargets | 目标使用 EntityRef；保留当前候选与已排除候选，排除记录含原因、精确条件与 evidenceRefs |
| targetSetCompleteness | `complete/partial/unknown`；确认集合事实与集合是否完整分别表达 |
| scope / contextId / conditionRefs | 适用工程/配置/入口与调用绑定；不同值版本的条件不得互换 |
| evidenceRefs / derivationRefs（查询投影） | evidenceRefs 保存直接依据；derivationRefs 由宿主构建反向支持投影，不进入原始事实 payload；来源闭包逐 Derivation 取得 |
| resolution | `confirmed/candidate/conflict/unresolved`，对应静态结论的确认程度；不表示运行已发生 |
| completeness | 下表所列独立结构；局部 confirmed 不保证范围完整 |

`confirmed` 可以确认“此调用的静态候选集合为 A/B”这一事实，但此时 `targetMode=candidateSet`，各目标仍是运行时选择候选。相同上下文可能重叠且语义互斥的结论才是 conflict；不同条件的结论和合法多态不是冲突。仅有 AI 线索且无分析器依据或人工确认时，不能升级成 confirmed；人工确认仍属于覆盖来源视图。

| Condition 字段 | 约束 |
|---|---|
| id / expression / bindings | 结构化表达式与 `symbolId/valueVersionId/contextId` 绑定；显示文本不能作为求值依据 |
| semanticProfileId / evidenceRefs | 表达式语义和支持模式、来源；语言/框架差异保留，不能用通用字符串比对证明相等 |
| evaluation / requiredInputs | `satisfied/unsatisfied/unknown` 限定到明确输入赋值；无具体值可以保留条件表达式及其分支，但不冒充已满足 |
| compatibility | 路径组合的相容/互斥/未知结果和依据由调用契约定义；计算上限/未支持运算需诊断 |

| Completeness 字段 | 约束 |
|---|---|
| complete | 是否完成**声明范围内**所需工作，不能表示已覆盖项目所有行为 |
| missingInputs / unsupportedModes | 输入 ID 或查询键、模式 ID、原因及影响；与“确认不存在”区别 |
| truncations | 截断的任务/阶段、预算维度、观察值及 budgetProfileId；预算值尚待 D04/D08 实测 |
| freshness | `current/stale`；旧事实不能进入当前确认链路或判定 |
| affectedScope / diagnosticRefs | 影响工程/配置/入口/对象/派生输出及可定位诊断 |

局部声明可同时 `resolution=confirmed` 与 `complete=false`；涉及必要关系/输入的缺口、截断或过期时不得发布完整确认链路或确定授权判定（包括条件化 allow/deny），可保留有据条件表达式和未知分支。失败输入与已知互斥不同：未知不改写为拒绝，不用一条可行候选证明整个场景开放。

Diagnostic 至少含 `id/code/message/scope/dependencyRefs/evidenceRefs/affectedRefs`。message 是展示说明，code 与结构化依赖用于失效；不以未发现检查自动断言漏洞。诊断文字也受不可信展示边界约束。

## 5. 原始位置与映射提议

坐标策略暂以 `coordinatePolicyId=raw-bytes-codepoints-v0.1` 表达提议，最终兼容需 M1-04/07 核对。SourceSpan 包含 `inputId/inputFingerprint/coordinatePolicyId/normalized/nativePositions/mappingRefs/mappingStatus`。

- `normalized.startByte/endByte` 是已登记输入**原始字节**中的零基、左闭右开范围；不先修改换行、Unicode 或编码。原始编码记录在输入清单；无损解码后才计算统一行列。
- 行/列从 1 开始；列按 Unicode 码点计数，制表符计一个码点。CRLF 作为一个换行，LF/CR 各自一个换行；结束行列表示右开端点，零宽诊断允许起止相同。
- BOM 占原始字节但不作为可见第一列字符；编码未知或无损解码失败时保存可取得的原生位置/字节范围及诊断，不提供伪统一行列。不固定所有输入均为 UTF-8。
- `nativePositions` 保留工具/版本、输入或虚拟文件、坐标单位、基数、端点约定及原生范围。工具使用字节、字符串单元或行列必须先登记，不能仅凭语言名称转换。
- `mappingRefs` 指向有输入版本的 Mapping：源/目标范围、`identity/virtual/generated/macro-expansion/macro-spelling` 类别、映射精度和 evidenceRefs。可一对多/多对一；宏使用处与定义处分别留存，生成源码身份不冒充业务源码身份。
- `mappingStatus=exact/partial/unavailable`；partial 保留分段和缺口，不扩成整个文件“精确映射”。映射链必须连续到所声明原始输入；缺业务映射时可展示真实生成/语义输入位置，并说明边界。
- 端点落在编码单元、码点或 CRLF 换行的内部且无法无损映射时，保留原生/原始字节范围和映射诊断，不猜测统一行列或无提示移动端点。

SourceSpan 不必要求每个结论都拥有业务源码范围：元数据、运行记录或缺源码的库边界使用各自定位方式。确认结论仍须有足够的可复核依据，不伪造文件位置以填字段。

## 6. 证据、推导与来源视图

| Evidence 字段 / 维度 | 独立语义 |
|---|---|
| id / inputId / inputFingerprint / locator | 载体版本与 SourceSpan、配置键/文档段落/运行事件等实际定位；证据去重不丢定位 |
| carrier | `source/config/metadata/document/comment/test/runtime-record`；说明材料类型 |
| production | `automatic/ai/manual/runtime`；说明此证据或注解如何取得，不替代依赖闭包 |
| semanticKind | `implementation-fact/business-interpretation/runtime-observation`；说明材料被解释为何种陈述 |
| scope / conditionRefs / capturedVersion | 配置、入口、适用条件与观察版本；运行记录不能泛化到全部请求 |
| accessRegistrationId / trustLabel | 指向输入/展示登记；`trustLabel=untrusted-content`，关系确认不赋予文本执行权 |

| Derivation 字段 | 约束 |
|---|---|
| ref / outputFactRefs / inputFactRefs / evidenceRefs | 自身和输入输出均用完整 FactRef，支持/反对证据分别记录；按 §2.1 校验版本化因果依赖，不把反向支持索引作为输入 |
| analyzerId/version / ruleIds / effectiveRuleSetId | 实际分析器和有效识别规则组合；指纹进入快照与依赖 |
| contextId / conditionRefs / bindingSummaryRefs | 调用/返回及主体/资源绑定的可追踪摘要 |
| method / analysisMode | `analysisMode=static/ai_assisted/manual_overlay/runtime_observation/mixed` 只为来源摘要，method 说明推导方式 |
| sourceClosure | 所有输入事实和辅助层的传递来源引用；不能由摘要枚举替代完整来源链 |
| supportingEvidenceRefs / opposingEvidenceRefs | 对具体输出项的支持和反对依据；不能仅给整篇报告一组引用 |

Claim 的不可变内容至少含 `ref/predicate/value/semanticKind/scope/conditionRefs/evidenceRefs/resolution/completeness`，查询时再附宿主构建的 derivationRefs 支持投影。文本解释是一项 Claim，内部多个可独立核实描述须拆项。自动读取文档所得的“文档如此描述”可确认，但不能因此确认实现已经发生；测试断言与测试执行结果分别留证。

自动基线冻结原始源码、必要语义输入和配置，分析时关闭 AI 与人工覆盖。AI 线索/解释和人工补边、删边、候选选择、业务确认各自保存独立层，记录基线快照、作者或模型/提示版本、理由、scope、输入指纹与复查状态；通过它们推导的结果继承全部来源。运行观察是另一补充视图，不能改变自动静态成绩。

AI 曾参与生成但已独立验证固化的识别规则，可在分析时不调用 AI 的自动基线中执行；规则包的生成来源与验证报告仍保留。这不允许将当次分析使用的 AI/人工事实重标为自动。独立人工标注真值、保留评估答案与分析输入隔离；契约说明中的预期表也不当作事实注入分析。

共享结论去重按完整语义键进行，保留所有独立 Derivation 与冲突依据；删除/停用一个来源后重算其他支持，不能就地修改底层事实。有效识别规则的覆盖机制详见资源/快照/规则契约，与目标工程授权组合是两套不同语义。

## 7. 扩展、读取与展示边界

适配器扩展用 `extensions[adapterNamespace]` 保存版本化原生信息和来源引用。公共 resolution、scope、身份、条件、完整性及证据不允许由扩展私有字段覆盖；公共检查无法解释的必需模式须诊断。协议/schema 不兼容的拒绝与部分批次行为在 M1-03 制定，不能静默丢字段后仍发布完整快照。

Evidence 的 inputId 与 accessRegistrationId 必须能解析到允许只读的输入；worker 能读取登记语义输入不等于 Web 可读取整个外部目录。查询/展示只通过完整 Evidence FactRef 及登记范围，不按逻辑证据 ID 选择某个 revision；移除源码或脱敏后说明证据已移除，不能补一个直接本机路径绕过限制。

源码、名称、文档、图标签、AI/人工说明及 URL 全部按不可信数据传递；证据被确认不代表可执行 HTML/SVG/脚本或任意访问 URL。输出按 Web/Markdown/Mermaid/HTML/SVG/嵌入数据的具体上下文处理；R08 的允许行为和执行反例归 M1-08，与 M1-07 协作。本草案未完成渲染器、链接策略选型或安全测试。
