## 3. 交叉复核问题与处理

| 发现 / 复核者 | 处理 | 最终状态 |
|---|---|---|
| 必要缺口仅阻断“无条件”判定，可能被误解为允许附假设的确定授权 / 资源、业务子代理 | 核心明确依赖必要缺口的确定 allow/deny（含条件化）均受限；有据表达式及未知分支可保留 | 已关闭并复核 |
| 坐标端点可能无法无损对应码点或 CRLF / 资源子代理 | 保留原始/原生范围和诊断，不猜统一行列或无提示移动端点 | 已关闭并复核 |
| 内存仓储提交可能被误写成耐久持久化 / 资源、上下文子代理 | StateOperation 增加存储边界与耐久性依据；明确现有采购示例仅支持进程内提交效果 | 已关闭并复核 |
| 当前源码全量重建无法恢复旧移动历史 / 业务子代理 | Snapshot 冻结 `identityRegistryRef`；同历史增量/全量使用相同身份登记版本。历史仅连续性元数据，人工/AI 匹配保留独立来源，评估答案不进入登记 | 已关闭并复核 |
| 主题字段拼写及 Condition 求值/相容字段有漂移 / 各作者与主代理 | 统一 evidenceIds/derivationIds/conditionIds、scope、Completeness、Condition 与候选目标状态；补明 InputRegistration/AnalysisProfile 的引用 | 已关闭并复核 |
| HTTP 例号总述漏 H8 / 业务子代理 | 改为 H1–H8；多入口检查覆盖反例仍保留 | 已关闭并复核 |
| 采购示例 README 末句称“未关联权限声明”未实现，与已有孤立输入扩展不符 / 依赖审计子代理 | 改为完整未关联诊断验收尚未实现，明确原始声明扩展已存在 | 已关闭，未改变示例源码 |
