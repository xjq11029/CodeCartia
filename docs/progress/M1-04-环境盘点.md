> 日期：2026-11-10｜范围：当前 Windows x64 会话｜用途：M1-04 实验准备
>
> 结论：Node/pnpm、Python、Git 及局部实验可用的 TypeScript/JDK/Roslyn 已具备；C/C++ 工具链、完整 .NET SDK 和现代 JDK 未确认具备。以下保留 2026-11-10 的环境观察，不是工具选型冻结或各语言分析验收。

## 2. 后续语言验证的候选系统工具

以下为恢复 Java/C#/C/C++ 验证时才需重新核对的环境候选，不是当前安装清单，也不阻塞初版 M1/G1、M3/G3 或 M6/G6。未安装不计为验收失败，延后本身也不计为验收通过。

| 状态 | 环境 | 扫描结论 / 原因 | 恢复验证时的准备 |
|---|---|---|---|
| 延后 | LLVM/Clang，Windows x64 | 未在所查 PATH/常见目录确认；C/C++ 真实语义实验需要前端工具链 | 恢复 C/C++ 验证后核验发行包、clang/clang++ 与所选分析接口；当前不安装 |
| 延后配套 | Visual Studio Build Tools 的 C++ 工具与 Windows SDK | 未确认可用 MSVC、Windows SDK、STL/系统头文件上下文；老 VS/VSTA 目录不构成完整工具链 | 恢复 Windows C/C++ 工程验证后按需准备工作负载/SDK，并记录版本/头文件根 |
| 延后 | .NET SDK，Windows x64 | 当前只有可用捆绑 runtime/Roslyn 与旧 .NET Framework 工具，未确认现代 SDK | 恢复 C# 验证后按目标框架/实验匹配 SDK；具体版本届时核验，当前不补装 |
| 延后 | 现代 JDK | 当前真实 JDK 为 9.0.1，未找到现代 LTS JDK | 恢复 Java 验证后按 JDT/Spring/原始项目输入匹配 JDK，核对 JAVA_HOME/PATH；保留旧观察 |

| 延后按工程 | Maven / Gradle | Maven 未确认；Gradle 8.10.2 缓存已存在但未启动核验 | 恢复 Java 验证后按工程依赖/元数据需要核对 wrapper，当前不启动核验或安装 |

上述候选类别沿用工程的后续扩展路线和已观察缺口，不据此冻结版本/分发组合。LLVM 的 Clang 提供语法与语义分析接口；LibClang/LibTooling 的适用边界见 [Clang 官方接口说明](https://clang.llvm.org/docs/Tooling.html)。公共产品依赖仍应按实际选型评估，不能把延后语言工具链整体准备设为首版前提。

## 5. 扫描与验证范围

本节保留 2026-11-10 的扫描方法与当时审批状态；2026-11-12 仅调整验证范围和准备顺序，没有追加安装或改写原始观察结果。

主代理和三个子代理只读检查了 PATH、常见 C/D 开发工具目录、相关卸载/SDK 注册、VS/Windows Kits、npm/pnpm 常见根、VS Code 与 Codex 捆绑模块、Java/Python 环境及 Gradle 缓存。第三方 Python 库通过模块/发行元数据定位，没有导入执行；Gradle 只读取分发和 JAR manifest，没有启动。没有递归扫描整盘或输出凭据/敏感环境变量。

“未确认”只限定上述所查位置，不意味着整台机器或所有虚拟环境都未安装。没有安装、下载、改系统 PATH/配置或继续修改实验代码；实验初稿与未完成验证状态保留。没有把包可定位或版本查询写成语义/框架/协议通过。

官方 LLVM 发布页和 .NET 支持版本页的打开动作未通过自动审批复核，返回的是复核未能完成，而非判定网站不安全。因此最新安装包/支持版本未核验，清单保留工具类别与后续核验要求。
