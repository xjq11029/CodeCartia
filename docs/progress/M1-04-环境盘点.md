## 2. 建议准备的系统工具

| 优先级 | 环境 | 扫描结论 / 原因 | 建议动作 |
|---|---|---|---|
| 优先 | LLVM/Clang，Windows x64 | 未在所查 PATH/常见目录确认；C/C++ 真实语义实验需要前端工具链 | 安装官方稳定发行包，核验 clang/clang++ 与所选分析接口；具体发行版本待核验 |
| 配套 | Visual Studio Build Tools 的 C++ 工具与 Windows SDK | 未确认可用 MSVC、Windows SDK、STL/系统头文件上下文；老 VS/VSTA 目录不构成完整工具链 | Windows C/C++ 工程实验时准备对应 C++ 工作负载/SDK，并记录版本/头文件根；自包含小样例可先行 |
| 后续完整 C# 栈 | .NET SDK，Windows x64 | 当前只有可用捆绑 runtime/Roslyn 与旧 .NET Framework 工具，未确认现代 SDK | 准备与目标框架/实验相符的受支持 SDK；建议选择 LTS 路线，具体版本待官方核验和输入匹配 |
| 建议补充 | 现代 JDK | 当前真实 JDK 为 9.0.1，未找到现代 LTS JDK | 准备与后续 JDT/Spring/原始项目输入相符的 LTS JDK，再核对 JAVA_HOME/PATH；保留旧实验基线 |
| 按需 | CMake / Ninja | 未在所查位置确认 | 原生 worker/LibTooling 或具体编译上下文需要时补；检查选定工具包是否已提供，避免重复 |
| 按工程 | Maven / Gradle | Maven 未确认；Gradle 8.10.2 缓存已存在但未启动核验 | 按 Java 工程依赖/元数据需求准备，优先核对工程 wrapper；不是 JavaCompiler 小实验的前置必需项 |

推荐安装类别沿用工程的候选技术路线和本机缺口，不据此冻结全部版本/分发组合。LLVM 的 Clang 提供语法与语义分析接口；LibClang/LibTooling 的适用边界见 [Clang 官方接口说明](https://clang.llvm.org/docs/Tooling.html)。

下列依赖尚未在工程中登记，不作为需要全局安装的系统 SDK，也不要求现在全部安装。版本应由原始输入、候选兼容和实验结果确定。

| 项目线 | 后续需要准备的依赖 | 本机核对与边界 |

| Vue | 对应版本的 SFC 编译器及必要 Vue 类型/元数据 | 未找到可独立加载的 @vue/compiler-sfc/vue；编辑器扩展不算工程依赖，Vue 不同版本分别验证 |
| React / Next | React/React DOM、对应类型及选定 Next 版本 | 未找到可独立加载的 react/react-dom/next 或 React 类型包；原生 JSX/TSX 符号实验不证明框架已可用 |
| Node 框架 | Express/Fastify/Nest 等实际样例的对应依赖 | 按各框架实验分别补，不同时安装全部框架 |
| Java / C# 分析与框架 | 选定 JDT/Roslyn 工作区及 Spring/ASP.NET 等原始输入需要的依赖/元数据 | 局部编译器 API 与完整框架/项目加载分开，项目/注解处理的只读边界仍须验证 |

## 5. 扫描与验证范围

主代理和三个子代理只读检查了 PATH、常见 C/D 开发工具目录、相关卸载/SDK 注册、VS/Windows Kits、npm/pnpm 常见根、VS Code 与 Codex 捆绑模块、Java/Python 环境及 Gradle 缓存。第三方 Python 库通过模块/发行元数据定位，没有导入执行；Gradle 只读取分发和 JAR manifest，没有启动。没有递归扫描整盘或输出凭据/敏感环境变量。

“未确认”只限定上述所查位置，不意味着整台机器或所有虚拟环境都未安装。没有安装、下载、改系统 PATH/配置或继续修改实验代码；实验初稿与未完成验证状态保留。没有把包可定位或版本查询写成语义/框架/协议通过。

官方 LLVM 发布页和 .NET 支持版本页的打开动作未通过自动审批复核，返回的是复核未能完成，而非判定网站不安全。因此最新安装包/支持版本未核验，清单保留工具类别与后续核验要求。
