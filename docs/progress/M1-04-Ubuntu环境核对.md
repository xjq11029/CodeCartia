## 2. 已确认的开发环境方案（后续可选）

用户此前明确选择：**Docker Engine＋Compose，语言工具放入固定镜像**，用于复用现有 Ubuntu 虚拟机。D13 将该多语言环境准备调整为后续可选事项，初版 JS/TS、Python 先复用已有 Windows 环境；Docker 安装不作为当前前置任务，也不设为产品用户必装条件。

- Windows 继续保留编辑器、仓库及现有可用工具。
- 后续启用 Ubuntu 容器方案时，安装前先核对已有软件包、仓库、架构和服务，避免依据 PATH 结果直接重复安装。
- 后续需要的语言 SDK、编译器及依赖可在实验镜像中准备；具体版本、内容指纹/镜像摘要及输入映射须登记后验证，不使用浮动标签冒充固定环境；当前不为延后语言创建镜像。
- 先启动小规模、有限并发实验，再按耗时/内存/磁盘测量调整。当前不建议仅因工具种类多就升级虚拟机资源。
- 源码/语义输入与缓存/报告分别处理，遵守只读取证边界；Windows SDK/MSVC 专属验证随 C/C++ 延后，初版 Windows 路径/进程等公共行为仍须验证。

Docker Engine＋Compose 是否实际可用、镜像获取、网络及各语言分析均尚未验证。开发容器的 Linux 空间也不能被当成被分析应用的实际运行空间。
