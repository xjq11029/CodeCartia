# M1 工程加载实验模式与预算

> 日期：2026-11-12｜状态：探索切片，有执行入口；未冻结产品支持与预算

本表登记 G1 首批工程加载实验实际覆盖的模式，用于反馈 M1-04/05/06/08。它不是 S01 的完整有限数据流细表，也不代替 M1-10 业务/授权模式或最终适配器能力矩阵。D13 的首版范围保持不变。

## 1. 模式与失败边界

| 实验模式 | 前提与输出 | 正反例入口 | 当前边界 |
|---|---|---|---|
| PL-JS-CONFIG | 根内静态 tsconfig/jsconfig，展开 include/exclude、extends、references；按每份配置建立输入集合 | project-loading 的 js-positive；JS 项目边界回归中的双配置、越界扩展与项目数预算 | 不求值 JS 配置、插件或构建；工程根外只读已登记 TypeScript 内置类型库，其他依赖缺失保留诊断 |
| PL-JS-ENTRY | additionalEntryFiles 显式登记根内无扩展名 JavaScript 源码，实际按 ScriptKind.JS 纳入主配置的 Compiler Program | 无扩展名入口中的跨文件引用/局部调用；主配置隔离、越界/junction、语言/shebang/编码和预算反例 | 路径和语言是技术输入登记，不解析执行启动命令；不把入口复制进所有引用配置，不因此确认 Node/框架语义 |
| PL-JS-REFERENCE | 已取得的静态源码/类型上下文，Compiler API 给出调用签名到声明的引用 | 独立跨文件别名/再导出正例；缺依赖、any 目标、同配置额外/漏调用反例 | confirmed 仅为 static-signature-reference；恢复签名和 unknown 不升级，不证明运行目标或完整数据流 |
| PL-PY-PROJECT | 静态 pyproject 的源码根与 src-layout 包，原始源码只读 | python-positive；dynamic-config、side-effect 与开发回归 | 不导入 setup/backend；动态元数据和已识别的不支持配置保留诊断，其他打包后端/布局与类型辅助/安装环境/框架未验证 |
| PL-PY-REFERENCE | 普通包内静态导入、相对导入和有限再导出，词法绑定可确定 | 包内跨文件声明/再导出正例、缺依赖、后置局部重绑、装饰器和动态命名空间反例 | confirmed 仅为 lexical-declaration-reference；runtimeTargetMode=unknown，可达性未判定 |
| PL-SOURCE-SPAN | 同次原始字节捕获生成 AST/Compiler 输入和指纹，坐标保留原始字节及 Unicode 码点 | 每语言的精确声明/调用/目标锚点；UTF-8/BOM/CRLF、错误范围及编码反例 | 只覆盖登记编码/位置；没有完成 Vue 虚拟文件/生成输入映射或所有输入编码 |
| PL-IO | 根内显式读取、只写所属 reports、拒绝链接路径及输入覆盖 | 两条语言项目边界回归与中央输入树/执行哨兵对照 | 当前 Windows 文件 symlink 用例受创建权限限制，junction/硬链接分别记录；并发文件系统替换未验证 |

所有源码与预期位置见[完整工程独立实验](../../examples/prototypes/project-loading/README.md)。支持模式和失败诊断来自版本化实现及实际输入，不由样例领域、角色名称或业务参数决定。

## 2. 探索资源配置

| 维度 | JS/TS 项目实验 | Python 项目实验 | 含义与限制 |
|---|---|---|---|
| 输入数 | 2048 | 512 | 包含实际登记配置/语义输入；达到上限有截断诊断 |
| 单文件 / 总字节 | 8 MiB / 64 MiB | 2 MiB / 16 MiB | 原始字节读取上限，不是产品工程规模承诺 |
| 目录 | 4096 | 4096 | 防止无界目录发现；链接拒绝单独检查 |
| 其他发现界限 | 50000 条目录项、100000 次查询、32 份项目配置 | 32 层导入引用 | 使用者可显式覆盖探索限额，报告保存有效值 |
| AST 事实遍历 | 300000 节点 | 单源码 100000 节点 | JS 在 Compiler Program 建立后约束遍历；Python 在解析后观察节点数，均不构成解析/类型检查的操作系统 CPU/内存硬限制 |

这些数值是本批有界实验的配置，不是冻结的 D04/D08 传播预算。小型正例的耗时和内存观察也不能证明真实大型项目性能。下一批需分别测量上下文深度、摘要迭代、候选数、路径/条件展开与召回损失，才可提出产品预算建议。

公共 [worker 实验](../../examples/prototypes/worker-runtime/SPEC.md)另登记 1 MiB 帧、每批 256 记录、64 批/4096 记录、单批 credit、独立日志/控制额度及宿主等待期限；它们属于传输资源配置，不能当作语义传播预算。具体有效值绑定其执行报告。

## 3. 完整性与后续冻结

JS/TS 的完整性范围是静态工程输入发现和事实捕获，调用目标未解析仍单列；Python 本切片始终保留一般传播、安装依赖、运行目标和类型/框架未覆盖。上层契约映射须保留这些范围与原因，不从 complete=true 推导完整调用图、业务成功或授权允许。

本批没有宣称 Vue/React/Node/Next/Python 具体框架、授权引擎或全部版本支持。需继续以独立预期验证框架事实、有限传播和业务/授权关键模式，记录版本、前提、正反例、预算与失败边界，再进入 D02/D04/D05/D06/D08/D10 的冻结决定。

结果与 G1 缺口见[本批进度记录](../progress/G1-工程加载与进程恢复验证.md)。
